# Пропозиції до дизайн-системи: Sanity + Bequant

Дата: 2026-10-19. Статус: **нічого не застосовано**, чекаю approve / reject по кожному ID.

Джерела: sanity.io (десктоп 1440, прокрутка, computed styles), bequant.com (те саме). Обмеження: анімації бачив лише статичними кадрами (Sanity-діаграма автоматизації була посередині циклу; Bequant-фігури це Lottie). Динаміку описую за кадрами й назвами секцій, не за кодом.

## Що ми вже маємо (не пропоную повторно)

Рядки 1px, dot-patterns (§8.11), mono-мітки, один акцент orange, tabs, stepper, segmented bars, hairline-фігури, `.chain` / `.flow` / `.levels` з Round 3. Нижче лише те, чого бракує або що треба закріпити правилом.

## A. Принципи інфографіки (з Bequant, підтверджено Sanity)

| ID | Принцип | Як це виглядає в них | Що змінюємо в DESIGN.md |
|---|---|---|---|
| P1 | **Фігура = один механізм, не діаграма з підписами.** 3–5 повторюваних примітивів (слот, пакет, лінія, вузол) | Bequant: черги як ряди порожніх закруглених слотів, пакети заповнюють слоти | Новий §8.15 «Figure»: список примітивів, заборона підписів усередині малюнка |
| P2 | **Монохром + один акцент тільки на тому, що змінюється** | Контури 1px сірі, лише сигнал (лінія графіка, активний пакет) помаранчевий | Закріпити: акцент у фігурі = `--accent`, усе інше `neutral/500–800`. Збігається з правилом hairline |
| P3 | **Сцена в картці: заголовок зверху, мономітка знизу** | `[TCPO] TCP Optimization` + 1 рядок опису, сцена з горизонтальними направляючими, внизу `BQN SOFTWARE` / `QUEUE 1` | Компонент `fig-card` (див. F1) |
| P4 | **Цикл показує «до → після», грає лише у вікні перегляду** | Короткі лупи на кожній картці | Правило руху в §11: цикл ≤ 8с, старт у viewport, reduced-motion = кінцевий кадр |
| P5 | **Число підтверджує фігуру** | Під фігурою `+10%` з дельта-чіпом і атрибуцією | Компонент `delta` (див. F4) |
| P6 | **Показуй справжній артефакт, не іконку** | Sanity: реальний код `hero.ts`, реальний Studio UI, реальні чат-підказки | Для нас: справжній текст Rule/Skill/Scenario у моно-панелі, а не декор |

## B. Компоненти й прийоми

Колонка «Конфлікт» = що в поточній системі це порушує.

### Фігури (Bequant)

| ID | Пропозиція | Спека (чернетка) | Конфлікт | Мій вердикт |
|---|---|---|---|---|
| F1 | **`fig-card`**: картка на чорному | `neutral/900`, border `neutral/850`, radius 4, pad 24. Верх: рядок заголовка (F2) + p2 опис `neutral/300`. Центр: сцена 1px-направляючі (горизонтальні, `neutral/800`). Низ: l2 мономітка `neutral/500`. Без тіні | Немає: §8.6 має dark card, але без сцени | **Так** |
| F2 | **Bracket-тег**: `[RULE] Назва` | Код у дужках: Geist Mono 600 uppercase, колір `--accent`; назва Inter p1 білим, одним рядком | Немає. Накладається на type-badge Rule/Skill/Scenario (§9.5) | **Так**, замінює колір-кодування типів у заголовках фігур. Бейдж лишається в списках |
| F3 | **Слот-ряд**: ряд контурних закруглених комірок | Комірка 28×36, radius 4, 1px `neutral/500`; стани: порожня, заповнена (`neutral/0` 15%), активна (акцент). Ряди 16px один від одного, мономітка ряду зліва | Немає | **Так**, головний примітив для «правило покриває N кейсів» |
| F4 | **`delta`**: число + дельта-чіп + атрибуція | n1/n2 значення, поряд коло 20px зі стрілкою `success/300` (на чорному), зверху l2 підпис, справа від вертикальної лінії ім'я l1 + компанія l2 | `success` у монохромній системі. Дозволено лише як іконка, не заливка | **Так** |
| F5 | **Лінійний графік з порогом** | Лінія акцентом 1.5px; горизонтальна пунктирна лінія порогу `neutral/500`; сітка тонкими 1px. Пунктир уже дозволений «всередині графіків» (§7) | Немає лінійного графіка в §8.7 | **Так** (малий, 1 приклад) |
| F6 | **Expand-іконка** у куті фігури | 16px іконка fullscreen, відкриває `<dialog>` з великою версією | Додає складність | Лише якщо фігура нечитабельна в картці. **Відкласти** |
| F7 | **Мета-ліворуч рядок**: `NEWS / 21 SEP` у колонці 1, зміст у колонках 2–3 | l2 мітка + l2 дата `neutral/500`, далі p1 заголовок. Нижні лінії 1px | Не конфліктує. Підходить для timeline дистрибуції (§9.5) | **Так** |
